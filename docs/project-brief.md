# Project Brief

## Objective

Create a living OSRS Ironman progression research system that can eventually recommend an explainable route for an actual account state. The objective is not maximum theoretical experience per hour and not a collection-log completionist route.

The system should help answer questions such as:

- What unlock should be pursued now, and why is now the right time?
- What does it unlock, replace, or bypass?
- Are there better alternatives given a drop, cash position, skill state, or available attention?
- What should run in parallel during a 30-minute, 2-hour, or several-day AFK window?

## Non-goals for this phase

- Publishing a universal linear rush guide.
- Treating an existing guide as authoritative strategy.
- Chasing 99s simply because a method is efficient.
- Awarding collection-log value to cosmetic or low-impact rewards by default.
- Assuming unattended or death-risk activity is acceptable AFK play.

## Core thesis

Progression is a graph over an account state. Activities create multiple outputs: skills, GP, supplies, transport, permanent convenience, gear, access, passive pipelines, and sometimes useful collection-log rewards. The preferred next action depends on both hard requirements and strategic timing.

## Baseline and challenge model

Established routes such as BRUHsailer are useful comparison baselines, not route law. In particular, cash targets must be decomposed into the purchases they fund. A long early blackjacking block is not assumed preferable to an activity that supplies GP while advancing skills, gear, resources, or access.
